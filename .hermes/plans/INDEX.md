# Plan Directory Index

This index is the durable source of truth for the status of every plan family in
`.hermes/plans/`. It was created in gap-remediation slice S10 and is maintained by
the campaign: S11 updates it with the campaign outcome.

Status values: `superseded` (a later document replaces it), `implemented` (the
planned work is confirmed in code and docs), `accepted` (a reviewer-terra PASS
accepted it), `open` (work is still in flight).

The gap-remediation campaign family and its S11 subfamily carry a baseline
literal Status of `implemented` in the tables below. These two Status cells are
snapshot cells only: they record the dated 2026-08-06 baseline and are
overridden, for effective status, by one deterministic latest-review rule,
stated here so no future review requires another INDEX edit:

- The effective S11 review is the latest committed file matching
  `.hermes/plans/2026-08-05-gap-remediation-s11-terra-review*.md`. The
  unsuffixed file has ordinal 1; a `-N` suffixed file has ordinal N; the
  highest ordinal is latest.
- If the latest effective review has verdict PASS, the campaign and S11 are
  effectively `accepted`, overriding their baseline Status cells. If the
  latest effective review has verdict FAIL (or no review is committed), the
  baseline cells stand and they are effectively `implemented`.
- The baseline Status cells are never edited to track reviews; effective
  status is always derived from the committed review files by the rule above,
  and this index intentionally records no current ordinal or current verdict.

Historical FAIL reviews are immutable. A FAIL document stays FAIL forever; it is
superseded only by an explicit later PASS review, recorded in the
`superseded-by` column. Slice S10 reformatted historical markdown with Prettier
(whitespace/wrapping only, semantically identical — see the S10 handoff); no
verdict text was edited.

## Coverage audit

is classified into exactly one family or justified subfamily above;
`INDEX.md` itself is excluded from coverage by design.

(`docs: make S11 review coverage durable`), which adds the first S11 review

  rows)

- Duplicates (file in more than one family): 0
- Excluded from coverage by design: `INDEX.md` (this file)

This explicitly dated snapshot supersedes the earlier fixed recounts (85
tracked files at S10 base `86274b9`; 91 at the S11 closeout commit `b538d1e`)
and stays truthful without further INDEX edits: every later committed file
matching `.hermes/plans/2026-08-05-gap-remediation-s11-terra-review*.md` is
owned by the S11 subfamily row's dynamic pattern, so it increments Tracked and
Covered together and preserves Unmatched 0 and Duplicates 0. Any other new
plan file still requires a one-row INDEX update, as before.
